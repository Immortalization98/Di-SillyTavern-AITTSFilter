# AI TTS Filter（AI 朗读过滤）

[English](README.md)

一个 SillyTavern（酒馆）前端扩展：在**酒馆自带的朗读**读出一条消息之前，先去掉不该读的结构内容，包括思考块、计算与骰子检定、状态栏、选项菜单、记忆表格、变量更新等。剧情、台词和描写照常用你现有的语音服务和音色朗读。

- **只删不改**：消息先切成带编号的片段，规则能判断的先判断，剩下的由你选的模型回答“跳过哪几号”。扩展只删除这些片段，并校验结果是原文的子序列，不会改写或添加任何文字。
- **只读聊天**：不修改聊天文件、消息数据和页面上的消息显示，包括美化效果。
- **用酒馆自带的朗读出声**：通过酒馆自己的 `/speak` 命令朗读，你的语音服务、音色表、按段朗读和播放设置都照常生效。

界面为简体中文。

## 功能

- **手动朗读**：接管每条消息上的朗读按钮，关掉开关即恢复原生行为。另有魔杖菜单“AI 朗读最新消息”和斜杠命令 `/aitts [楼层]`、`/aitts-preview [楼层]`、`/aitts-filter 文本`。
- **自动朗读**：默认关闭。自带排队，连续的消息不会互相打断；“继续生成”只读新增的部分。
- **预览**：显示哪些内容会被跳过，划线并标出原因（规则 / 模型 / 手动）。
  - **纠错模式**：点片段在“读 / 不读”之间切换，可以按纠正后的结果朗读，并记住这次的纠正。
  - **意见修正**（预览里的 **提意见**）：用一两句话说哪里不对。过滤模型给出这条消息的修改，以及格式方案的规则和说明；每条规则都先拿这条消息和方案里的样例检查，你确认后才保存。这样学到的规则以后直接判定同类消息，不再问模型。意见和这条消息会发给过滤模型的服务商。也可以选 **补充样例**，只把改好的这条消息存为样例（锚点），不新增规则。
- **过滤模型**，四选一：
  - 自定义接口（填写地址、密钥和模型）；
  - 已有的连接配置；
  - 当前聊天的连接；
  - 只用规则，完全不调用模型。
- **缓存**：按设备保存在浏览器的 IndexedDB 里，只存被跳过的片段编号，不存聊天原文。
- **格式方案**：用几份样例教会扩展某张卡或某个预设的格式，详见下文。
- **出错处理**：模型超时或回答异常时，按设置改为只用规则、朗读原文或不朗读。

## 和同类项目的区别

| 项目 | 做什么 | 区别 |
| --- | --- | --- |
| 酒馆自带的朗读选项（跳过标签、正则、只读引号） | 固定规则 | 认不出不带标签的状态行和计算过程；“跳过标签”还会把 `<content>` 这类包着正文的标签一起删掉 |
| SillyTavern-TTS-Regex-Presets | 按卡切换手写的朗读正则预设 | 正则要自己写、自己维护；不调用模型，没有预览 |
| SillyTavern-BreezeTTS2、VoiceLoom | 自带语音流程，用模型打情绪或说话人标签 | 替换了酒馆自带的朗读，而不是在它前面做过滤 |

## 需要什么

- SillyTavern **1.19.0** 或更新版本。
- 已开启酒馆自带的 **TTS** 扩展，并配置好可用的语音服务。
- 如果要用模型过滤：任意兼容 OpenAI 的对话模型即可，便宜、快、不带推理的模型就够用。我们实测 flash 一类的模型，每条消息约 2.5 秒。

## 安装

- **从酒馆里安装**：**扩展 → 安装扩展**，粘贴本仓库地址，选择只给自己装还是给所有用户装。前端扩展不用重启酒馆，刷新页面即可。
- **手动安装**：把文件夹复制到 `data/<用户>/extensions/Di-SillyTavern-AITTSFilter/`（只给自己）或 `public/scripts/extensions/third-party/`（所有人），然后刷新页面。

## 设置

在扩展设置里打开 **AI 朗读过滤** 面板：

1. **过滤模型**，三选一：
   - **自定义接口**：填写兼容 OpenAI 的地址（`…/v1`），粘贴密钥后点 **保存**，再填写或选择模型。
   - **已有的连接配置**：选一个连接配置。
   - **当前聊天的连接**：直接用聊天的连接。

   也可以把 **过滤方式** 设为只用规则，完全不调用模型。
2. **接管消息上的朗读按钮** 保持开启。想自动朗读，就打开 **自动朗读新消息**。
3. 注意：过滤之后，酒馆自带朗读的设置照样生效。如果开着“只读引号”或“只读对白”，旁白和描写仍然不会读，需要的话把这两项关掉。

## 使用

- 点消息上的朗读按钮，或用魔杖菜单的 **AI 朗读最新消息**。
- 在消息的“更多”菜单里点漏斗图标，打开 **朗读预览**，查看哪些内容会被跳过。
  - 点 **纠错** 可以改判，然后选 **按此朗读并记住** 或 **加入样例**。
- 面板里的 **试运行** 可以过滤任意粘贴进来的文字，方便调试提示词。

## 格式方案（锚定）

不同的卡和预设，输出格式各不相同。**格式方案**通过几份样例学会其中一种格式。

- **样例**：一条完整原文，加上应该读出来的“正文”。
  - 可以在预览里点 **纠错 → 加入样例** 添加，也可以粘贴原文和正文。
  - 正文和原文有少量不一致时（比如显示用的正则隐藏了几个字），会逐条列出，确认后照常加入。
- **自动规则**：从样例里学出几种固定形式的规则，包括标签、正文标签、行首文字（如 `📍`、`结算：`）、括号类型、“名称：数值”行。
  - `div` 这类通用排版标签不学。
  - 宽泛的规则要在两份样例里都出现，才默认开启。
  - 每条规则都可以单独开关。
- **AI 分析**：调用一次模型，写出一段简短的格式说明，并补充一些规则。每条规则都先拿样例检查，通过的才给你确认采用。
- **附带样例**（可选）：每次请求都把样例作为示例一起发给模型。
- **回测**：用当前设置把样例重新过滤一遍，列出多删和漏删的地方。
- **绑定**：方案可以绑定**角色卡**或**预设**，随时换绑。优先级：角色卡 > 预设 > 全局默认。每个方案默认最多 3 份样例，可以调到 10 份；每份样例原文默认最多 5 万字，可以调到 20 万字。

## 隐私与存储

- **消息原文会发给你选的过滤模型**，经由酒馆后端转发。如果它和聊天模型不是同一家服务商，就多了一个能看到你消息的接收方。
- **自定义接口的密钥**保存在**酒馆自带的密钥库**里（标签“AI 朗读过滤”），扩展只按编号引用，扩展设置里不存密钥本身。
  - 保存过滤密钥不会改变聊天连接正在用的密钥。
  - 没有保存过滤密钥时，聊天的密钥也绝不会被发给过滤接口。
- **过滤缓存**存在本设备浏览器的 IndexedDB 里，只有片段编号和类别。
- **格式方案的样例**保存在扩展设置里，跟随账号；其中包含样例消息的原文。
- 带清理地卸载扩展，会删除缓存、设置和保存的过滤密钥。

## 限制

- 消息生成完成后才开始朗读，暂不支持边生成边朗读。
- `/speak` 发起的朗读，在朗读事件里拿不到消息编号。音色按角色名查找，所以用户消息使用默认音色。
- 模型仍可能判断失误，但它只能删除整段，不能改字。可以用预览和格式方案来纠正。

## 开发

```bash
node --test
```

- `src/core/`：纯逻辑模块（切分、规则、提示词、合成、流水线、方案规则、样例、分析），单元测试在 `tests/`。
- `dev-tools/mock-llm.mjs`：本机模拟的 OpenAI 兼容接口，可以返回角色扮演回复、过滤结果和格式分析结果。
- `dev-tools/mock-tts-recorder/`：只用于测试的语音服务，记录送来朗读的文字。
- `dev-tools/eval/`：用真实模型测准确率的样例。在装有本扩展的酒馆页面控制台里运行：
  ```js
  const { runEval } = await import('/scripts/extensions/third-party/Di-SillyTavern-AITTSFilter/dev-tools/eval/run.js');
  await runEval();
  ```
